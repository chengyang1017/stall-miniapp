# Phase 18：商家商品搜索、筛选、排序和分页

本阶段仅提供代码及索引迁移，没有执行迁移、部署或任何测试。保留 Phase 15–17 的本地修改。

## 查询和权限

新增 `GET /v1/merchant/stores/:slug/product-search`，沿用 catalogRoute 的服务端会话、店铺归属和 owner/manager 角色校验。所有产品、草稿、分类和版本校验 SQL 均绑定已授权的 store_id；不是公开顾客接口。

参数：

| 参数 | 允许值／含义 |
| --- | --- |
| q | 最多 100 个字符。商品名称、分类名称按字面部分匹配，完整商品 ID 精确匹配；完整 UUID 输入仅匹配 ID。`%`、`_`、反斜杠按字面处理 |
| categoryId | 空值或分类 UUID |
| kind | all / product / draft |
| state | all / active / inactive / scheduled |
| soldOut | all / yes / no，指商家手动状态 |
| stockMode | all / finite / unlimited |
| stockState | all / low / zero |
| discount | all / yes / no |
| sort | created / updated / name / priceAsc / priceDesc / stockAsc / stockDesc / scheduled |
| limit | 整数 1–100，小程序固定 30 |
| cursor | 服务端上一页返回的游标，30 分钟有效，绑定店铺、全部查询条件和分页大小 |

拒绝未知、重复参数、非法枚举和分页值。参数使用占位符绑定；排序表达式来自后端白名单。商品状态通过独立筛选器搜索，不通过名称推断。

商品与 `state='draft'` 的独立草稿表以 UNION ALL 合并，再统一过滤、排序、分页。已发布或已放弃草稿不返回。正式商品的上架、下架、待定时、手动售罄条件排除草稿；同时选择“草稿 + 已上架”等矛盾条件会返回空结果，不会自动忽略条件。

上架指 active 或计划时间已到；下架不包含待定时上架。售罄是独立的手动标记，可与上架状态组合。零库存和低库存仅匹配有限库存，低库存为 `0 < 数量 <= 阈值`。草稿按其中有效的库存配置匹配；无效或尚未填写的数值为未知值，不能当成零。

“有折扣”指存在非负且低于原价的有效折扣价格，包含尚未开始及已经结束的优惠；价格排序使用原价。此查询不改变顾客实际计价规则。

## 稳定分页及并发边界

采用游标分页，排序主键后固定按“条目类型 + UUID”升序排列。金额和库存规范化为整数排序键，名称使用 lower(name) 和 C 排序规则（不是拼音排序）；时间排序键为 UTC。不限库存、未填写或无效的草稿数值，以及无计划时间的条目，相关排序中均在末尾，升降序一致。

每一页在短暂的 `REPEATABLE READ READ ONLY` 数据库事务内计算店铺数据版本及读取结果。版本包含商品 ID、业务版本、库存版本、修改时间，当前草稿的 ID／版本，及分类 ID／名称。任何会影响列表的既有 API 修改、库存预留或释放、增删商品／草稿及分类变更，都会使后续翻页返回 409，要求重新搜索／刷新，避免移动排序键造成重复或漏项。事务不会跨请求保持，不锁商品行，不修改订单或库存。

计划状态以首屏数据库时间 asOf 计算，后续页沿用该时间；新建商品排除在这一次查询以外。刷新会取得新的时间与数据版本。正在浏览的结果不是实时推送，计划到期或数据变化后请刷新。分页失败时不会把不同版本的列表拼接起来。

版本摘要需在数据库内扫描当前店铺商品、草稿和分类的精简版本字段，名称包含搜索也可能扫描该店铺数据。没有安装全文／拼音／trigram 扩展，没有宣称海量商品性能已经实测；大型或高频下单店铺可能较常需要刷新。客户端只接收每页结果，不拉取全部商品或全部商品 ID。

## 客户端和既有操作

输入文字不发请求，点击“搜索／刷新”或键盘搜索才查询；清空按钮清空关键词，重置按钮清空全部条件。选择筛选或排序即执行新查询。每次修改条件先退出批量模式、清空勾选，使旧请求序号失效。未提交关键词时旧结果暂停操作。

请求同时校验递增序号和店铺上下文，旧结果不能覆盖新查询。追加结果按“类型 + ID”去重，追加页面只向视图传输新增显示行，避免反复传输全部描述和草稿原始表单。提供首屏加载／错误／空结果、加载更多／失败重试、数据变化时刷新提示，以及下拉刷新和触底加载。

批量管理只使用已显示的正式商品 ID，不使用游标推断其他商品、不选草稿。加载更多保留勾选但不会自动勾选新条目；全选仅选当前已加载的正式商品。批量操作仍使用既有窄字段 PATCH，逐项统计失败，完成后重查首屏；失败项只有在刷新后仍显示时才保留勾选。

新增按 ID 读取正式商品／草稿的受权 GET，编辑、复制和草稿表单无需再从最多 500 条列表中查找来源。复制继续默认下架、不手动售罄、不限库存、无定时计划；不会继承原库存余额、库存历史和计划。图片对象引用及生命周期不变。支付、订单、预留、释放、历史快照、顾客可售性规则均未修改。

## 微信开发者工具手动体验

1. 打开现有项目，以已有方式进入商家商品管理。本地演示可直接体验；云端需由维护者另行完成迁移、发布后端并配置已有商家会话，本任务没有执行这些操作。
2. 输入部分商品名／分类名后点击搜索；粘贴完整 ID 搜索。使用清空、重置及下拉刷新。
3. 组合“饮料 + 已下架 + 低库存”，或“待定时上架 + 有折扣”。分别查看手动售罄、零库存、草稿；矛盾条件应为空。
4. 逐一选择八种排序，留意相同价格、库存及时间的条目顺序，以及不限库存和不完整草稿在末尾的位置。
5. 匹配结果超过 30 条时加载更多／触底加载。超过 500 条的云端商品仍可搜索、翻页、按 ID 编辑和复制，不以首批 500 条为范围。
6. 在筛选结果进入批量管理，全选后加载更多，原勾选保留、新条目不自动选中。改筛选／排序／搜索文字后勾选立即清空；草稿不可选。完成批量操作核对成功和失败数量。
7. 从结果编辑、复制、继续编辑草稿并保存返回，列表重新查询；保存的商品若不再符合条件，不会强行留在旧筛选结果中。
8. 使用另一个已有商家会话修改商品或产生库存变化，再加载下一页，界面应提示数据变化并要求刷新；模拟弱网时快速切换查询，旧响应不应覆盖新结果。
