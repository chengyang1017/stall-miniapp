# 云端文字客服（Phase 23）

仅完成源码与静态检查，未运行测试、数据库迁移、部署或微信环境联调。

## 启用依赖与数据

沿用现有 PostgreSQL、微信登录 `/v1/auth/wechat` 和 `auth_sessions`，以及 `merchant_members` / `permittedStore`；没有新增认证体系或第三方服务。需要已有迁移 001—012 后再由操作者按正常流程应用 **013_support_messages.sql**，本阶段不执行。开发迁移脚本仅更新预期编号，没有运行。

`support_conversations` 每店每顾客唯一，保存 UUID、原有身份 subject、open/closed 状态、最后消息序号与时间、双方已读水位。`support_messages` 保存服务端 UUID、会话内递增序号、角色、发送者 subject、幂等 UUID、text 类型、正文和服务端时间。不收集头像、手机号、姓名或地址。message_type 为未来类型扩展预留，本阶段数据库约束只允许 text，不实现图片。所有时间为 timestamptz，界面转换北京时间 UTC+8。

状态字段目前默认 open；closed 会拒绝新发送，不新增关闭/重新打开的业务操作。

## API

以下每项均须现有 Bearer 会话认证。顾客前缀 `/v1/stores/:slug/support`：

- GET `/conversation`：仅自己的会话，尚未发送时返回 null，不创建空会话。
- GET `/messages?limit=30&before=序号`：最新/更早消息；`after=序号` 增量同步，与 before 互斥。
- POST `/messages`：`{content,clientKey}`，首次发送时事务内创建自己的唯一会话。
- POST `/read`：`{through:"消息序号"}`，只单调推进本人收到消息的已读水位，不超过会话最新序号。
- GET `/unread`：自己在该店收到的商家消息总未读数。

商家前缀 `/v1/merchant/stores/:slug/support`：

- GET `/conversations?limit=30&cursor=...`：授权店铺会话、最新摘要、时间、各会话未读数。
- GET `/conversations/:id/messages`：相同消息分页参数。
- POST `/conversations/:id/messages`：回复指定会话，正文与幂等字段同上。
- POST `/conversations/:id/read`：相同已读水位参数，推进店铺侧共享已读水位。
- GET `/unread`：完整店铺未读顾客消息总数。

现有 owner、manager、staff 店铺成员可处理客服，不授予普通顾客商家权限。所有商家会话操作同时限定 store_id 与会话 ID；顾客端不接受顾客 ID 或任意会话 ID，而是由认证 subject 定位。没有权限的店铺返回 403，不存在/不可访问的会话返回 404，身份失效 401，幂等冲突/会话关闭/分页集合变化 409，限流 429，参数 400，过大正文 413，内部异常 503。不会返回 subject 或在日志写正文、令牌。

## 顺序、幂等和未读

在事务内锁定会话行分配递增 seq，插入消息与更新会话最后时间原子提交。排序与消息分页使用 seq，不使用客户端时间。已读更新 greatest(旧值,请求值)，统计按对方 sender_role 且 seq 大于服务端水位计算，覆盖完整历史，读请求重复安全。店铺侧已读为多商家账号共享，不是每个员工独立未读。

唯一约束 `(conversation_id,sender_subject,client_key)` 保证同一发送重试只返回原消息；同编号改变内容/角色返回 409。前端发送锁防止重复点击，失败保留输入及原编号供重试。用户主动选择修改未确认消息时会警告原消息可能已送达，新内容视为新发送。草稿及待确认编号仅保存在当前页面内存，离开并销毁页面后不保证保留；不把正文或令牌另存日志。

每个认证发送者跨会话最多 20 条新消息/分钟。数据库事务级 advisory lock 串行化该发送者的限流检查，多进程一致；幂等重试先返回旧消息，不计新消息。基础限流不是完整反垃圾系统，不阻止多账号滥用。

## 分页和同步

默认 30 条、最大 100，正文 1—500 Unicode 字符，请求体最大 4096 字节；SQL 使用绑定参数和固定字段，语句超时 5 秒。消息返回每页按 seq 升序供界面展示；before 向前加载，after 增量拉取，按 ID 去重。聊天页可见时每轮结束后间隔 12 秒轮询，读请求互斥，页面隐藏/卸载停止，旧身份和旧请求结果丢弃。一次增量最多 30 条，积压会在后续轮询或手动刷新继续补齐。普通网络失败保留已成功读取的消息；身份/权限失效清空受保护内容。返回页面重新读取最新一页。

会话列表以 `(last_message_at,id)` 倒序游标分页，带当前店铺全集消息序号摘要版本。分页中收到消息导致排序变化则返回 409，要求重新加载，避免静默漏项。列表本身在打开、重新显示、下拉或点击刷新时同步，不在后台轮询。工作台未读每 30 秒前台刷新，隐藏停止；个人中心显示时刷新。未读来自后端，不限于分页；聊天页仅标记当前已展示到的序号，之后到达的消息不会被提前标记。

## 双模式与入口

有效现有店铺云端配置时，客服始终走云端：无登录则提供微信登录按钮，无权限或网络失败只显示错误，绝不回退本机消息。没有配置时继续使用原 `stall_support_messages_v1` 同设备演示聊天，从收件箱进入商家演示回复，不上传演示数据。首页、订单详情、个人中心统一进入现有 support-chat；商家工作台到 support-inbox，商家选择会话后以固定会话 ID 进入同一聊天页面。

## 手动体验（启用环境后）

1. 操作者自行准备已应用 001—013 的非生产数据库、现有微信身份配置及商家店铺授权；本阶段没有替操作者执行。
2. 顾客 A 在个人中心/首页/订单详情进入客服，登录、发文字；顾客 B 登录另一微信身份，同店发送，核对会话互不串联。
3. 商家工作台查看未读，进入客服收件箱，分别打开 A/B 会话回复；对照聊天顶部会话标识确认目标，顾客前台等待轮询或下拉查看回复、已读状态。
4. 超过 30 条历史加载更早消息；超过 30 个会话加载更多。分页期间新消息改变列表时按提示刷新。
5. 断网发送，确认输入与失败状态保留；恢复后直接重试同一编号。切换店铺/退出身份，确认不再展示旧店会话。隐藏页面不再轮询。
6. 移除有效云端配置后核对本机演示仍可从顾客和商家入口互相回复，云端记录不会被带入。

## 未验证与范围

真实 PostgreSQL DDL、并发/限流/幂等行为、HTTPS 域名配置、微信登录与真机跨设备使用尚未运行验证。大量会话的全店摘要与未读统计需要实际规模下评估；查询有 5 秒超时保护，没有声称经过压测。没有推送、订阅消息、WebSocket、附件、自动客服、工单或支付改动。下一阶段优先安排获授权的数据库和微信联调、安全与性能验证，不自动开发后续阶段。
