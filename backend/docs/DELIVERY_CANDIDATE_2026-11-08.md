## 开发者和商家在现场必须共同完成（尚未验收）
- [ ] 商家确认一个正式小程序 AppID、一个直连微信支付商户号以及账号主体、经营类目与必要的审批；商家拥有账号和最终操作权。
- [ ] 商家在自己的腾讯云账号购买资源并授权最小运维权限，确认备案/域名、HTTPS 和小程序服务器域名白名单。
- [ ] 在腾讯云隔离测试环境演练数据库备份、完整恢复、权限最小化与 `001–037` 迁移；对正式数据先备份后迁移，逐一核对哈希/数据库角色。**禁止**使用 `migrate-dev.mjs` 对远端正式数据库执行迁移。
- [ ] 按 `WECHAT_LIVE_PAYMENT_HANDOFF.md` 在服务器私密环境配置微信支付证书、平台公钥、APIv3 密钥、商户号、回调 URL；确认公钥轮换与通知重试处理。密钥不得提交 GitHub、聊天或小程序包。
- [ ] 导入商品、配送规则、商家成员权限，演练顾客下单、商品库存、优惠、接单、配送、取消、售后、评价、客服及地址等端到端业务流程。
- [ ] 真机检查顾客端和商家端登录、头像、手机号授权、跳转、弱网/回弹及页面布局；检查微信平台审核要求。
- [ ] 在**商家明确批准**、可监控的正式环境内进行小额真实支付与退款；分别验证支付通知重复/乱序、超时取消后到账、未付款订单、微信查询结果未知、部分退款、全额退款、冲突终态和断网恢复。核对金额、库存与实际商户账户的状态。
- [ ] 官方微信商户平台交易、退款和结算账单由商家下载核实，核对手续费、结算日期、订单交易号、退款流水及银行入账；当前 `wechat-bill-reconciliation` 接口**仅比较用户整理的指定记录**，并不自动下载或鉴别官方账单，也不确保整份账单完整。
- [ ] 异常到账由有权限的商家人工核对并决定补偿方案，必要时通过官方商户后台执行退款；本系统的 `refund_required` 与人工备注**不能**证明退款成功。核对告警、日志权限和操作审计保留策略。
- [ ] 双方核对生产安全：权限、备份、告警、限流、日志脱敏、数据保留、密钥轮换、回滚预案及对外隐私协议。
- [ ] 商家书面确认真实收款启用窗口和交接结果；移交服务器、数据库、商户号、小程序、域名、操作手册及维护/故障联系人。

## 生产启用顺序与回退
1. 先完成代码离线验收、账户/证书准备、迁移及隔离环境验收。服务端 `WECHAT_PAY_LIVE_ENABLED`、`WECHAT_PAY_LIVE_REFUNDS_ENABLED`、`WECHAT_PAY_REFUND_RECONCILE_ENABLED` 保持关闭。
2. 商家批准后再按风险从低到高进行真实支付联调；退款及退款查询任务必须另行单独批准启用。前端正式构建开关要与后端状态匹配，不能让用户创建无支付渠道可用的订单。
3. 如出现资金核对异常，**先停止新付款/退款入口并保留审计与账单证据**。不要删除已收款/退款记录、回退已执行的财务交易或重复提交不同商户单号。
4. 对数据库或代码执行回滚前，先取得当前备份并分析真实资金与已处理订单；迁移 `037` 含追加式审计记录，未经审计确认不得破坏性回滚。

## 明确范围
本单商家版本的开发侧代码可以进入交付候选流程；正式账户验真、腾讯云部署、真实资金测试、官方完整账单与银行结算核对仍是未完成的生产验收事项。若验收发现阻断问题，必须修复后重新测试，不能靠清单勾选视为成功。
