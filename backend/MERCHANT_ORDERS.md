## 列表和汇总 API

继续使用 `GET /v1/merchant/stores/:slug/orders`，新增参数：

| 参数 | 规则 |
| --- | --- |
| q | 最多100字符；编号部分匹配、收货人姓名及手机号部分匹配；完整 UUID 走订单 ID 精确查询 |
| state | all／latest、new、accepted、preparing、delivering、delivered、cancelled、abnormal；兼容 other 表示取消和异常 |
| from／to | 两个都填写或都不填写；YYYY-MM-DD，首尾包含，最多366天；同一天即指定日期 |
| limit | 默认30，整数1–100；小程序固定30 |
| cursor | 上一页的 nextCursor，30分钟有效 |

不传日期可以遍历全部历史，不再只返回前100单。返回保留 orders、pendingCount、hasMore，增加 nextCursor、counts、matchingCount、asOf 和 canManage。旧的列表调用仍可读取第一页，完整翻页由增强后的主订单页完成。

既有 `/orders/summary` 扩展为完整店铺 counts：全部、待接单、已接单、备货中、配送中、已送达、已取消、配送异常及取消／异常合计，同时保留 pendingCount 和 pendingStatus='new'。此接口固定为全店统计，不接受筛选参数。工作台已有调用不需修改，即可继续同步同一 new 定义。

所有接口继续在原 orderWorkflowRoute 验证会话和 permittedStore；列表沿用既有商家成员读取权限，状态／ETA 写入仍需要 owner／manager。服务器返回 canManage 仅用于界面禁用，写接口始终重新校验角色。顾客订单列表和详情的本人访问规则没有改变。

SQL 均绑定已授权 store_id，搜索词／日期／状态／游标值参数化，状态使用白名单；不接受用户拼接 SQL 或排序字段。`%`、`_`、反斜杠按字面搜索。不添加包含收货人、手机或会话令牌的日志。

## 分页和一致性

以 `created_at DESC,id DESC` 排序，并以同一元组进行游标查询；使用数据库 UTC 微秒时间，避免相同创建时间排序不稳定或截断精度。游标绑定商家主体、店铺、搜索、状态、日期和分页大小。

第一页记录数据库时间 asOf。后续页排除创建时间晚于该边界的新订单，刷新才纳入它们；新订单不把正在翻阅的旧页挤动。每页在 REPEATABLE READ READ ONLY 短事务中读取：完整匹配集合的摘要、匹配数量、全店状态数量及当前页快照。

摘要包含匹配订单 ID、履约状态和 updated_at。匹配集合内已有订单状态／ETA／库存到期等变化、成员进入或离开筛选集合时，后续页返回409要求刷新，避免跨页静默重复或漏项。与当前筛选无关的队列变化不使其失效。长事务延迟提交、创建时间早于首屏边界的订单也会通过集合变化触发刷新。

counts 始终覆盖当前事务看到的完整店铺，不受分页、日期或搜索限制。matchingCount 是本次查询边界和条件下的总数，不能与未筛选的标签数量混为一谈；页面明确说明这一点。新订单到达后，标签可能大于当前查询匹配数，刷新可重新查询。

每条 SQL 设置5秒超时。单页最多4000个商品行，超过或金额无法安全表示时明确失败，不截断或静默舍入。正常 checkout 每单最多40行，因此固定30条页无需一次载入全部订单。

新增 `sql/012_merchant_order_query_indexes.sql`，仅建立店铺／状态／创建时间／ID 与店铺／创建时间／ID 组合索引。既有迁移未修改；正常执行顺序为001–011后再012，本阶段未执行。列表仍需要现有预计时间、库存等结构；索引不会自动部署。

包含匹配和集合摘要仍需处理授权店铺内的相关数据，未引入全文搜索扩展或统计缓存。尚未做真实数据量性能验证；大店查询建议先按日期和状态收窄。

## 页面与会话

沿用 admin-orders 的卡片、状态标签、备注／联系方式、原因、预计时间和照片入口。增加独立的取消、异常筛选，同时保留取消／异常合计；日期起止相同可查单日，支持今天和全部日期。

关键词输入不逐字请求，点击搜索或键盘确认才查询；筛选／日期切换直接执行新查询，重置游标和旧勾选。旧请求用递增序号隔离，不覆盖新结果。继续加载按 ID 去重，仅追加新显示行，不反复传输整份历史列表。

有首屏加载、匹配数量、空结果、失败重试、加载更多、全部加载状态和下拉刷新。失败不改用本地订单；状态数量没有成功读取时显示“—”，不是假零。

私有查询上下文包含 API、店铺和当前会话身份，不放入 WXML 或日志。离开页面会清空客户卡片、分页缓存及勾选；返回重新读取。退出登录或切换店铺／会话后清空旧查询、联系方式搜索内容、预计时间输入和订单数据，不复用其他店铺游标。

## 批量接单和备货

仅增加客户端串行队列，复用原 `POST /orders/:id/status`，没有重复状态机或新批量写接口。

- 每次最多50个已加载、当前显示的待接单／已接单订单。全选不包含未加载订单，超过50单时要求手动选择，避免暗中只选一部分。
- 支持逐项勾选、取消选择、取消全选、退出批量模式。更换查询清空旧勾选；加载更多保留已有勾选，不自动选中新订单。
- 只支持 new→accepted、accepted→preparing。混选状态时，不符合当前操作的条目计为失败，不绕过状态机，也不自动执行其他转换。
- 操作前锁定提交并确认选中数量，执行中显示进度；不会发出重复队列。每条实际请求都重新验证会话、店铺、角色、锁定订单并执行原支付／库存／状态检查。
- 原有限库存未支付预留限制仍会拒绝推进状态，不伪造付款。无预留订单是否可推进仍依原状态机处理。
- 展示成功、失败或未确认数量和逐条失败信息；网络丢失响应不能认定成功，也不宣称服务器已经回滚。失败可能包括并发状态变化、预留到期、权限、未执行或网络不确定。
- 刷新首屏和全店统计后，仅保留仍显示且符合可选状态的失败项。没有批量删除、取消、异常或送达。
- 若离开页面或会话改变，后续未发出的队列停止并计为未执行；已经发出的请求仍可能在服务器完成。返回后重新读取核对。

## 单订单操作

接单、备货、开始配送、取消和异常复用原写接口及原因要求。只有服务器明确确认成功后才更新卡片；不再符合当前状态筛选时移出。数量不靠前端猜测加减，重新读取全店统计。刷新失败时保留已确认的卡片状态，并说明列表／数量待核对。

操作失败不提前修改卡片；若原接口已因库存超时取消订单，重新读取应显示服务器实际状态，而不是假装已回滚。预计时间失败保留输入，成功检查服务端确认；批量模式不混入单订单按钮。

送达照片和完成配送仍进入原 delivery-proof 页面，本阶段没有修改其上传凭证、对象存在／类型／大小校验、店铺权限或支付限制，也没有增加无照片直接送达路径。没有修改订单状态写入分支、支付系统、退款、库存预留／释放或订单历史金额快照。
