# Phase 19 商家经营分析

## 实现范围与运行状态

新增独立 `admin-analytics` 页面，从现有商家工作台“服务与数据 → 经营分析”进入。没有引入依赖，没有改动账单、订单状态、微信支付、库存扣减／预留／释放、商品搜索和图片生命周期规则。

本次仅完成源码及静态 TypeScript／Node 语法检查。没有编写、生成或运行测试，没有连接数据库验证，没有执行迁移、部署或 Git 操作。云端使用前仍需维护者另行授权并完成后端代码更新和迁移。

## 数据来源与权限

- 云端：`GET /v1/merchant/stores/:slug/analytics` 及 `/analytics/export`，均验证已有服务端会话、店铺访问权和 owner／manager 角色。每条订单、订单行、当前商品和分类查询都限定授权店铺。SQL 值使用参数绑定，排名字段严格白名单。
- 本地：仅无云端配置时使用 `stall_demo_v1` 当前商品和现有演示订单加载器，标记“本地演示数据”。演示订单来自当前库存演示订单及旧 `stall_demo_orders_v1`，沿用已有按 ID 去重和过期处理。云端失败不会切换到演示数据。
- 云端只选择经营所需字段，不选择顾客姓名、电话、联系信息、地址、备注、配送照片或支付凭据，不向客户端返回原始订单。
- 默认币种 CNY；云端仅统计 CNY 订单。业务日期和小时在 SQL 中明确按 `Asia/Shanghai` 转换。日期过滤转换为 UTC 时间边界，使用现有 `(store_id,created_at)` 索引。订单时间来自已有 checkout 由数据库生成的 created_at，不接受分析客户端伪造下单时间。

## 各指标口径

统一按订单创建日期归属，包含开始和结束日期。

| 指标 | 口径 |
| --- | --- |
| 订单总数 | 日期及商品／分类条件下的去重订单数，包含取消订单 |
| 已确认支付订单数 | 当前为 0，原因见下 |
| 未支付订单数 | 未取消且数据库 payment_status='unpaid' |
| 取消订单数 | 云端 fulfillment_status='cancelled'；演示兼容旧 canceled／refunded 履约标签 |
| 订单总金额 | 未取消订单金额；无商品／分类筛选时为 orders.total_cents（含配送费） |
| 已确认支付金额 | 当前为 0，原因见下 |
| 未支付订单金额 | 未取消、payment_status='unpaid' 订单的相应口径金额 |
| 客单价 | 未取消订单金额 ÷ 未取消订单数；按分四舍五入；零订单为 0 |
| 商品销量 | 未取消订单中匹配商品的下单件数，包含未支付，页面明确称“下单件数” |

存在商品或分类筛选时，总览／趋势的订单金额改为**匹配商品订单行快照金额，不含配送费**；订单数量仍按订单去重。页面和 CSV 均显示这一口径。相同商品的多个订单行不会增加重复订单数；不同商品的订单数不可直接相加当成总订单数。

取消订单不计商品数量、有效商品订单数、订单金额、未支付金额及客单价，但保留在创建订单总数和小时分布内。配送异常不会自动视为取消或退款。分析不修改任何状态，也不推断退款成功。

### 收款限制

现有系统 checkout 只创建 unpaid 订单，源码没有完整的微信支付验签成功回调或可核验结算记录。payment_events 现有通用字段不足以单独证明事件已经通过支付验证。因此本阶段**确认支付订单数和金额全部保持 0**，不把数据库中孤立的 paid 标签当作验签证据。

未取消但状态不是 unpaid 的订单被列为“其他未核验支付状态”，既不计确认收款，也不冒充待支付。接单、配送、送达、库存预留／扣减均不构成收款依据。本地无论标签如何均不认定真实收款。

未来若接入可信支付确认，必须同时更新总览、趋势、排行和导出的统一口径；本阶段没有实现支付接入、退款对账或支付日期收入报表。当前报表不是会计结算或银行到账证明。

## 排行、趋势和商品表现

- 排名支持下单件数、商品订单金额、确认支付金额、未取消订单数，前 10／20／50。相同值固定按商品键排序。无有效商品订单时不填造排行榜，确认支付排序的金额当前均为零。
- 每日趋势包含订单数（含取消）、未取消订单金额、确认支付金额、商品下单件数。无订单时显示空状态；CSV 可以记录实际为零的日历日期，不生成虚构数据。
- 24 小时分布按北京时间创建小时计数，包含取消订单。
- 商品表现每页 30 项，包含当前商品的真实零销量行；库存单独标示不限、零库存、低库存和手动售罄，不把低销量推断为缺货。
- 商品金额取 `order_items.line_total_cents`，该字段由订单行中的历史 unit_price_cents × quantity 生成；不读取商品现价计算历史金额。本地使用已保存的 subtotal 快照。
- 有商品 ID 时按 ID 聚合；展示名称取最近一笔匹配订单的商品名称快照，当前名称另列。没有匹配订单的当前商品使用当前名称并显示零。删除或改名商品仍保留订单历史统计；无法关联时库存显示未知。
- 缺少商品 ID 的旧订单只能按历史名称分组；不同同名商品可能无法区分，此限制不能通过当前商品猜测修复。
- “最近有效订单”取未取消匹配订单的最近创建时间。

查询在短暂的 REPEATABLE READ READ ONLY 事务中读取一致数据，聚合在后端完成，不拉取未经授权的客户端订单列表。翻页和云端导出携带报表摘要；统计或库存展示发生变化时返回 409，要求刷新，不拼接不同版本数据。客户端校验请求序号和店铺上下文，清除旧搜索展示，重复相同加载请求不会重复发出。

## 历史分类与迁移

新增 `sql/011_sales_analytics.sql`：

1. order_items 增加 category_id_snapshot、category_name_snapshot，不加当前分类外键，不回填旧历史。
2. 插入触发器从订单所属店铺内的商品及分类取得真实分类快照。无需修改 checkout 的金额、状态或库存业务逻辑。
3. 新增 order_items(order_id,product_id) 查询索引。

本地新建演示订单同样补存可选分类快照，不修改任何支付、订单状态和库存处理规则。

旧订单历史分类未知，只计入“全部”或“未记录历史分类／无分类”，绝不归给当前分类。当前分类下的商品即便显示零销量，也不意味着它过去属于该分类；表示在所选历史分类和日期内没有可信的匹配记录。分类改名／删除后，历史快照保留，查询可提供历史分类选项。单个商品的历史分类名称摘要最多展示 20 个并标明总数，筛选和金额统计不截断。

迁移顺序为已有 001–007 → 008 → 009 → 010 → **011**。未改动任何旧迁移，开发迁移器仅更新预期序列到 011。没有执行。云端缺少所需字段时明确返回迁移未就绪，不用假数据降级。

## CSV 与限制

总览、商品销售明细、每日趋势均可导出。云端在相同权限校验接口返回 CSV 内容及严格格式的文件名；不创建公开下载地址、不把会话令牌放进 URL。客户端沿用现有账单的 USER_DATA_PATH UTF-8 写文件及 shareFileMessage 分享模式；开发者工具不能分享时说明文件已保存，需要真机分享。

CSV 有 UTF-8 BOM、CRLF、所有单元格双引号包裹、内部引号翻倍，保留中文、逗号和换行。对空白／控制字符后以 =、+、-、@ 开头及危险制表符／换行开头的单元格加单引号，避免公式执行。文件名包含 overview／products／daily 及日期范围；演示文件另加 demo 前缀。

导出只含汇总指标、商品 ID／快照名称、历史分类、当前库存、有效订单时间，不包含顾客个人信息。导出商品明细为所选范围完整聚合结果，不限于当前显示的 30 条。

为保护服务器，本次同步分析和导出限制为：

- 日期最多 366 天；搜索词最多 100 个字符。
- 最多 10,000 个匹配订单、50,000 个订单行、10,000 个关联／匹配当前商品以及 10,000 个分类选项；超过会报错，不截断后假装完整。
- 每条 SQL 最长 5 秒；商品 CSV 最多 5,000 项；文件最多 5 MiB。
- 未实现后台异步导出或超大数据仓库统计；大店需要缩小范围。尚未做实际数据库或大数据量运行验证。

## 微信开发者工具手动体验

1. 从“商家工作台 → 服务与数据 → 经营分析”进入。无云端配置时应明确显示本地演示；没有订单时所有指标为零，当前商品可列零销量。
2. 选择今天、昨天、近 7／30 天、本月、上月，或自定义日期。切换四种趋势、查看北京时间 24 小时分布。
3. 用商品快照名、当前名或完整 ID 搜索；选择分类。旧订单应落入未知历史分类，新演示订单会保存分类快照。
4. 切换四种排行及前 10／20／50，查看零销量商品、当前库存和最近有效订单。金额均不是凭现价重算。
5. 本地以正常下单流程创建未支付演示订单，查看订单金额／下单件数增加但确认收款仍为零。有限库存待支付订单过期取消后，刷新查看取消计数及金额剔除。
6. 按现有流程编辑商品名称／价格／分类，再返回分析，历史名称、金额和分类不应被当前值覆盖。
7. 分别导出三种 CSV；在真机分享到文件工具或 Excel，检查中文、引号、换行、口径说明和隐私字段。超过限制应明确失败。
8. 云端需维护者另行应用代码及迁移并配置已有商家会话后体验；本任务没有执行。检查权限失败、数据为空、网络失败、切换筛选时旧响应不覆盖，以及翻页／导出期间数据变化提示刷新。
