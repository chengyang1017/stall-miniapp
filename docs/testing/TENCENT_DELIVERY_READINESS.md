| 顺序/阶段 | 可自动执行内容（未来授权后） | 必须停止的条件/人工闸门 |

| 4. 数据库准备 | DBA创建正式库与独立迁移/运行角色，执行前述目标核验/备份/迁移 | 数据库写入单独批准；必须在启动Node前完成schema验收 |
| 5. 发布制品 | 版本化`/opt/stall/releases/<release-id>`，仅backend运行源码、package/lock和审定元数据；CI构建小程序另交微信工具 | 不打包整个工作区/.git/.env/.bak/测试/私人回执；release来源必须是审查过的候选版本 |
| 6. 服务配置 | systemd非root、EnvironmentFile、WorkingDirectory、Restart有界、NoNewPrivileges/只读系统路径和受限写目录；Nginx TLS/限流/请求体/超时/脱敏日志 | 当前不存在这些生产模板；升级及证书续期须演练。root依赖安装与curl管道脚本不作为默认方案 |
| 7. 数据及启动批准 | 独立授权建立真实商户/店铺与核验subject的成员关系；商家设置真实商品、营业配送与起送门槛；受控启动Node | Node启动会自动运行库存/定位清理任务，这是数据库操作，不是只读动作；不自动造商品/订单/支付 |
| 8. 验收及切流 | 内网业务就绪检查→HTTPS路由/微信登录→小流量→真机→发布审批 | `/health`成功不足；失败保留日志/旧release，不自动破坏性修库或重建 |
| 9. 运维交接 | 证书/磁盘/错误率/DB连接/worker失败/备份告警、备份恢复演练、联系人和值守文档 | 无RPO/RTO、告警接收人、恢复证据不得签“可运维” |

未来发布入口的默认动作应为plan；安装、迁移、服务启动、切流分别需显式授权与环境ID。重复执行按摘要和资源身份判断，不覆盖未知文件，不自动申请域名/备案/证书或给微信账号授权。自动化只能复用同一Node业务与原迁移，不另造本地商城。

## 8. 下一步顺序与签收闸门

1. 不购买服务器也可推进正式云配置构建、生产部署模板/迁移工具及离线回归；独立端导航已完成源码修复与三端编译。其余部署能力仍是待实现设计，本次未扩展范围。

3. 单独授权安全隔离的真实PG测试，补足事务/并发验收。另行授权HTTPS Staging、秘密配置和真实店铺/微信绑定，完成手机验收。
